# Start here

**Phase:** PRE-PRODUCTION. **Source:** master bible v0.1. **Working revision:** v0.2 draft. **Production:** blocked.

> We do not start making the full game until the game works on paper.

The hypothesis is: **a deterministic town where knowledge lets you manipulate cause and effect is fun.** A logically consistent design is necessary, but only unfamiliar players can test the fun hypothesis.

## Authority

The source concept remains **CANON v0.1**. New design choices are **PROPOSED v0.2** until adopted. The timeline preserves disputed source entries with audit references. Paper traces use a declared set of proposals; a successful trace does not resolve those proposals by itself.

Formatting repairs such as `3,0005,000` → `3,000–5,000`, `610` → `6–10`, and `640 360` → `640 × 360` recover obvious intended ranges/dimensions. Changes to event times, motives, item access, or ending rules are not formatting repairs.

## Immediate work

1. Review the audit and proposed rule set.
2. Run the paper prototype with unfamiliar players using its facilitator script.
3. Record observations without prompting the desired witness solution.
4. Revise failed assumptions and rerun affected scenarios.
5. Close Gate G only with the required evidence; authorize a small software prototype separately from full production.

No source checkmark proves validation. Gates A–F mean the source describes the topic, not that its feasibility has been established.
